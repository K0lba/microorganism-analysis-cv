# Форматы данных microorganism-analysis

## 1. Входные изображения

Поддерживаемые расширения:
- PNG
- JPG / JPEG
- BMP
- TIFF

Изображение представляется массивом NumPy:
- grayscale: (height, width)
- color: (height, width, channels)

Индекс пикселя:
- x — координата по горизонтали, начиная с 0 слева;
- y — координата по вертикали, начиная с 0 сверху;
- начало координат — верхний левый угол изображения.

Для цветных изображений необходимо документировать порядок каналов.
OpenCV обычно использует BGR, а библиотеки визуализации часто ожидают RGB.

## 2. Входные видео

Для каждого видео необходимо хранить:
- experiment_id — идентификатор эксперимента;
- source_path — путь к исходному файлу;
- frame_index — индекс кадра в исходном видео, начиная с 0;
- timestamp_s — время кадра в секундах относительно начала видео;
- width_px, height_px — размеры кадра;
- fps_nominal — заявленная частота кадров, если известна.

При субдискретизации frame_index должен соответствовать исходному видео,
а timestamp_s — времени исходного кадра, а не порядковому номеру
кадра в сокращённой последовательности.

Приоритет источников времени:
1. Исходные временные отметки кадров (PTS), если доступны.
2. Временные отметки контейнера или декодера.
3. Расчёт frame_index / fps_nominal, только если известно,
   что частота кадров постоянная.

Если время кадра неизвестно, его нельзя считать достоверным.

## 3. Маски сегментации

Для каждого кадра сохраняется набор объектов.

Каждый объект содержит:
- detection_id — идентификатор обнаружения в данном кадре;
- mask — бинарная маска объекта размером height x width;
- bbox_xyxy — границы [x_min, y_min, x_max, y_max];
- centroid_xy — центр [x, y] в пикселях.

Маски разных объектов должны иметь отдельные идентификаторы.
Перекрытие масок и разделение соприкасающихся объектов должны
обрабатываться явно, в зависимости от алгоритма.

## 4. Таблица наблюдений

Одна строка — один отслеживаемый объект в одном обработанном кадре.

Обязательные поля:
- experiment_id: string
- track_id: string или integer
- frame_index: integer
- timestamp_s: float
- centroid_x_px: float
- centroid_y_px: float
- area_px2: float
- perimeter_px: float
- length_px: float
- width_px: float
- aspect_ratio: float
- circularity: float
- roundness: float
- convex_hull_area_px2: float
- solidity: float
- displacement_px: float
- velocity_px_s: float
- segmentation_quality: float или null
- tracking_quality: float или null

Дополнительные поля:
- area_um2, perimeter_um, length_um, width_um;
- displacement_um, velocity_um_s;
- relative_area_change, relative_length_change;
- experiment metadata и параметры калибровки.

Если величина не вычислена, сохраняется null/NaN,
а не фиктивный ноль.

## 5. Единицы измерения

Без калибровки:
- координаты и линейные размеры — px;
- площадь — px^2;
- скорость — px/s.

При известном размере пикселя s в микрометрах на пиксель:
- длина_um = длина_px * s;
- площадь_um2 = площадь_px2 * s^2;
- скорость_um_s = скорость_px_s * s.

Если пиксели имеют разный физический размер по осям X и Y,
необходимо использовать отдельные коэффициенты калибровки.

## 6. Экспорт

CSV:
- одна строка на наблюдение;
- имена столбцов фиксированы;
- время — секунды;
- единицы измерения указаны в названиях столбцов.

Parquet:
- те же логические поля;
- числовые и временные столбцы сохраняют типы;
- null используется для отсутствующих значений.

Исходные изображения и маски не следует хранить в каждой строке таблицы.
Их можно сохранять отдельно, ссылаясь на experiment_id, frame_index
и detection_id.
